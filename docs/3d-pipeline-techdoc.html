3D dak-modelleringspipeline
Architectuur, data-acquisitie en reconstructie

Doelpubliek: LIDAR-/photogrammetrie expert Versie: v4 (multi-gebouw) Datum: mei 2026

Dit document beschrijft de huidige werkwijze van het programma dat een 3D-model genereert voor een Belgisch adres, met als doel een externe LIDAR-expert in staat te stellen om gericht feedback te geven op zwakke schakels (LiDAR-keuzes, classificatieconventies, reconstructie-algoritme, coverage-strategie).

1. Overall Architecture

Drie executie-omgevingen werken samen: een Next.js front-end op Vercel, een serverless Python pipeline op Modal.com, en een browser-gebaseerde Three.js viewer. Geen eigen infrastructuur of containerorkestratie buiten Modal & Vercel.

3. Data-acquisitie (detail)

Vier bronnen: Geopunt (geocoding), Capakey (kadaster), Basisregisters (gebouwen), 3D GRB WMS (hoogte/type). LiDAR komt uit een aparte S3 bucket.

Geocoding

Geopunt v4 (Vlaamse overheid). Geen Nominatim/OpenStreetMap. Voordeel: levert direct Lambert72 (EPSG:31370) zonder eigen reprojectie, en is gespecialiseerd op Vlaamse adressering inclusief huisnummer-bus-codes.

def _load_tile_index(cache_dir: Path) -> dict:
    idx_path = cache_dir / "tile_index.json"
    if idx_path.exists():
        return json.loads(idx_path.read_text())

    import boto3
    from botocore import UNSIGNED
    from botocore.config import Config

    s3 = boto3.client("s3",
        config=Config(signature_version=UNSIGNED),
        region_name="eu-central-1")
    paginator = s3.get_paginator("list_objects_v2")
    index = {}
    for page in paginator.paginate(Bucket=S3_BUCKET, Prefix=S3_PREFIX):
        for obj in page.get("Contents", []):
            filename = obj["Key"].split("/")[-1]
            m = re.search(r"ES_(\d+)_(\d+)\.copc\.laz$", filename)
            if m:
                index[f"{m.group(1)}_{m.group(2)}"] = filename

    idx_path.write_text(json.dumps(index))

Tile lookup per gebouw

def _find_tile_url(index: dict, cx: float, cy: float) -> str | None:
    tile_x = int(cx // 500) * 500
    tile_y = int(cy // 500) * 500
    for dx in (0, -500, 500):
        for dy in (0, -500, 500):
            key = f"{tile_x + dx}_{tile_y + dy}"
            if key in index:
                return COPC_BASE + index[key]
    return None

Eerst exacte containment (tile waarvan lower-left corner ≤ centroïde < lower-left + 500), daarna acht buren. Dit vangt randgevallen op waar het gebouw op de tile-grens ligt.

Tile download met caching

def _download_tile(tile_url: str, cache_dir: Path) -> Path:
    import requests as req
    filename = tile_url.rsplit("/", 1)[-1]
    cache_path = cache_dir / "tiles" / filename
    cache_path.parent.mkdir(parents=True, exist_ok=True)
    if cache_path.exists() and cache_path.stat().st_size > 1024 * 1024:
        return cache_path
    with req.get(tile_url, stream=True, timeout=600) as r:
        r.raise_for_status()
        with open(cache_path, "wb") as f:
            for chunk in r.iter_content(chunk_size=4 * 1024 * 1024):
                f.write(chunk)
    return cache_path

Cached in Modal Volume roofer-cache (persistent over function calls). Sanity-check: bestaande file moet ≥ 1 MB zijn om als geldig te tellen (anders re-download).

3D GRB — alleen metadata, geen geometrie

Belangrijke nuance:

Layer GRBGEBL1D2 = LOD 1 extrusie-hoogtemodel zonder dakvlakken. Wij gebruiken het enkel om nokhoogte, gebouwType en kwaliteit op te halen — niet als geometrie-bron. De echte LOD 2.2-geometrie komt uit de roofer-reconstructie op de DHMV II puntwolk. Geen 3D GRB mesh download.

Volledige Next.js API-route voor 3D GRB

async function get3DGrbInfo(x: number, y: number): Promise<Hoogte3D | null> {
  try {
    const delta = 40 // 80m venster rond centroide
    const url = `${WMS_3DGRB}?SERVICE=WMS&VERSION=1.3.0&REQUEST=GetFeatureInfo` +
      `&LAYERS=GRBGEBL1D2&QUERY_LAYERS=GRBGEBL1D2` +
      `&INFO_FORMAT=${encodeURIComponent('application/geo+json')}` +
      `&CRS=EPSG:31370` +
      `&BBOX=${Math.round(x - delta)},${Math.round(y - delta)},` +
      `${Math.round(x + delta)},${Math.round(y + delta)}` +
      `&WIDTH=101&HEIGHT=101&I=50&J=50&FEATURE_COUNT=5`

    const res = await fetch(url)
    if (!res.ok) return null
    const data = await res.json()

    const features = data?.features
    if (!Array.isArray(features) || features.length === 0) return null

    const hoofd = features.find((f) => f.properties?.ENTITEIT === 'Gbg') ?? features[0]
    const p = hoofd.properties
    return {
      nokhoogte:   parseVlaamsGetal(p.HN_P99)   ?? parseVlaamsGetal(p.HN_MAX),
      grondniveau: parseVlaamsGetal(p.H_DTM_GEM) ?? parseVlaamsGetal(p.H_DTM_MIN),
      gebouwType:  p.LBLTYPE ?? null,
      footprint3d: parseVlaamsGetal(p.OPPERVL),
      kwaliteit:   p.H_KWAL ?? null,
    }
  } catch { return null }
}

4. Point Cloud Processing

Wij doen geen eigen PDAL-pipeline. We downloaden de hele 500m × 500m LAZ-tile en geven die door aan roofer, samen met een Lambert72 footprint-polygon. Roofer crop'pt, classificeert en filtert intern.

Inlezen

Productieroofer's interne LASlib-gebaseerde reader (geen Python-binding)
Debug-padlaspy[lazrs] in debug_roofer() Modal function — alleen voor inspectie (bbox, classificaties tellen, point-count per gebouw)
StreamingNiet gebruikt. We downloaden de hele tile lokaal. COPC's octree-streaming voordeel benutten we (nog) niet.

Classificatie — kritisch punt

Non-standard classificatie in DHMV II open data

De DHMV II tiles op het AWS open-lidar-data bucket gebruiken bijna uitsluitend classification = 1 ("unclassified"). De ASPRS-standaard zou klasse 6 ("building") moeten zijn voor dakpunten, maar deze data is niet door een building-classifier gegaan. Resultaat: roofer's default (--bld-class 6) levert geen dakpunten op.

Onze fix: roofer --bld-class 1 --grnd-class 2 … — we vertellen roofer expliciet om klasse 1 (unclassified) als bouwpunten te interpreteren. Klasse 2 (ground) is al correct geclassificeerd in de DHMV II data.

Cropping & filtering

Geheel intern in roofer:

  • Spatial crop op de footprint-polygon (Lambert72 EPSG:31370 GeoJSON)
  • Terrain detection via grondpunten (class 2) — fallback buffer_tile strategie
  • Outlier rejection via robust plane-fitting (RANSAC-achtig)
  • Footprint kan worden gebufferd/gesimplificeerd (zie roofer log: "Simplifying and buffering footprints...")

5. Dakvlakdetectie & 3D-modellering

Twee paden: roofer LiDAR-reconstructie (primair) of synthetic geometrische reconstructie (fallback). Beide leveren een trimesh.Trimesh in absolute Lambert72 coords (Z-up), die later worden gecombineerd en geherprojecteerd.

Roofer algoritme

Roofer past plane-fitting + region growing toe op de gefilterde puntwolk binnen de footprint. De exacte methode is gedocumenteerd in TU Delft's 3DBAG paper. Vereenvoudigd:

  1. Crop puntwolk op buffered footprint
  2. Identificeer terrain via grondklasse + lokale grid
  3. Voor het dak-gedeelte: plane-fitting op meerdere oriëntaties (RANSAC-variant)
  4. Region growing om coherente dakvlakken te vormen
  5. Snijden van de vlakken om nok- en hooklijnen te bepalen
  6. Output: per gebouw meerdere LOD-niveaus (0, 1.2, 1.3, 2.2)

Output: CityJSONSequence

Een tekst-bestand met JSON Lines: één regel header met transform (scale + translate), daarna één regel per gebouw als CityJSONFeature. Vertex-coördinaten zijn integers relatief tot transform.translate, geschaald door transform.scale. Zie Bijlage B voor een volledig voorbeeld.

CityJSON-parser (LOD-keuze)

def _cityjson_to_mesh(cj_path: Path):
    import numpy as np
    import trimesh

    transform_info = None
    all_verts, all_faces = [], []

    with open(cj_path) as f:
        for line in f:
            obj = json.loads(line.strip())

            if obj.get("type") == "CityJSON":
                transform_info = obj.get("transform")

            elif obj.get("type") == "CityJSONFeature":
                raw = obj.get("vertices", [])
                if not raw: continue
                v = np.array(raw, dtype=np.float64)
                if transform_info:
                    sc = transform_info.get("scale", [1, 1, 1])
                    tr = transform_info.get("translate", [0, 0, 0])
                    v = v * sc + tr
                base = len(all_verts)
                all_verts.extend(v.tolist())

                # LOD-prioriteit
                preferred = ["2.2", "2.1", "1.3", "1.2", "0"]
                for co in obj.get("CityObjects", {}).values():
                    geoms_by_lod = {}
                    for geom in co.get("geometry", []):
                        lod = str(geom.get("lod", "0"))
                        geoms_by_lod.setdefault(lod, []).append(geom)
                    chosen = next((l for l in preferred if l in geoms_by_lod), None)
                    if not chosen: continue
                    for geom in geoms_by_lod[chosen]:
                        gtype = geom.get("type", "")
                        bounds = geom.get("boundaries", [])
                        surfaces = []
                        if gtype == "Solid":
                            for shell in bounds: surfaces.extend(shell)
                        elif gtype in ("MultiSurface", "CompositeSurface"):
                            surfaces = bounds
                        for surf in surfaces:
                            ring = surf[0] if surf else []
                            for i in range(1, len(ring) - 1):
                                all_faces.append([base + ring[0],
                                                  base + ring[i],
                                                  base + ring[i + 1]])

    if not all_verts or not all_faces: return None
    return trimesh.Trimesh(
        vertices=np.array(all_verts, dtype=np.float64),
        faces=np.array(all_faces, dtype=np.int32),
        process=False,
    )

Naïef fan-triangulation van elke ring (werkt voor convexe polygonen — alle CityJSON surfaces uit roofer zijn convex). Geen earcut, geen normaal-validatie.

Synthetic fallback

Triggers: tile niet gevonden in S3, roofer crash, of mesh-hoogte < 1m (roofer output bevatte alleen LOD 0). De fallback maakt een procedurele geometrie op basis van footprint + nokhoogte + gebouwType.

Schilddak via PCA + Oriented Bounding Box

# Schilddak via oriented bounding box (centroïde-relatief om PCA te doen)
centroid = pts.mean(axis=0)
pts_centered = pts - centroid
cov = np.cov(pts_centered.T)
_, eigvecs = np.linalg.eigh(cov)
long_axis = eigvecs[:, 1]
angle = np.arctan2(long_axis[1], long_axis[0])
rot = np.array([[np.cos(-angle), -np.sin(-angle)],
                [np.sin(-angle),  np.cos(-angle)]])
rotated = pts_centered @ rot.T
min_xy, max_xy = rotated.min(axis=0), rotated.max(axis=0)
# OBB-hoeken in geroteerde frame, dan terug
corners_rot = np.array([[min_xy[0], min_xy[1]], [max_xy[0], min_xy[1]],
                        [max_xy[0], max_xy[1]], [min_xy[0], max_xy[1]]])
rot_inv = np.array([[np.cos(angle), -np.sin(angle)],
                    [np.sin(angle),  np.cos(angle)]])
obb = corners_rot @ rot_inv.T + centroid

# Nok = lijn over de lange as, ingekort met 25% aan beide uiteinden (hipped roof)
long_len = float(np.linalg.norm(obb[3] - obb[0]))
cl_a = (obb[0] + obb[3]) / 2
cl_b = (obb[1] + obb[2]) / 2
nok_dir = (cl_b - cl_a) / np.linalg.norm(cl_b - cl_a)
nok_inset = long_len * 0.25
nok_a = cl_a + nok_dir * nok_inset
nok_b = cl_b - nok_dir * nok_inset
goothoogte = nokhoogte * 0.6   # GOOT_RATIO

Geometrische heuristiek — geen LiDAR. Goothoogte vast 60% van nokhoogte (typische Vlaamse woning). Geen dakkapellen, geen hoekverdrag, geen ruimtelijke complexiteit.

Geen LOD1 als basis

Wij gebruiken het 3D GRB LOD 1 blok NIET als geometrische basis.

De LOD2 reconstructie komt puur uit de LiDAR puntwolk via roofer. 3D GRB wordt alleen geconsulteerd voor metadata (nokhoogte als input voor synthetic fallback, gebouwType voor plat-detectie heuristiek). Beslissing om geen hybride te bouwen: 3D GRB's LOD 1 is een extrusie zonder dakvlakken, en hybridisatie met LiDAR voegt complexiteit toe zonder duidelijk kwaliteitsvoordeel boven roofer-direct.

6. Metingen & Output

Dakoppervlakte-meting

Werkelijke dakoppervlakte ≠ footprint-oppervlakte (vanwege helling). Hellings-correctie:

function berekenDakOppervlak(
    footprint: number | null,
    nokhoogte: number | null,
): number | null {
  if (!footprint) return null
  if (!nokhoogte) return footprint
  let factor = 1.05
  if (nokhoogte >= 5 && nokhoogte < 8) factor = 1.15
  else if (nokhoogte >= 8 && nokhoogte < 12) factor = 1.30
  else if (nokhoogte >= 12) factor = 1.05
  return Math.round(footprint * factor)
}

Footprint zelf berekend via shoelace-formule op de Lambert72 polygoon uit GML.

Three.js viewer — face-normal-based material splitting

De viewer (in public/lod2-viewer.html) bouwt twee materialen op (dak met procedurele dakpannen-canvas, muur met baksteen-canvas) en splitst de faces op basis van face-normaal: 

// Per face: bereken normaal via cross-product, route naar dak of muur
const n = new THREE.Vector3();
for (let f = 0; f < faceCount; f++) {
  const i0 = oldIdx[f*3], i1 = oldIdx[f*3+1], i2 = oldIdx[f*3+2];
  a.fromBufferAttribute(pos, i0);
  b.fromBufferAttribute(pos, i1);
  c.fromBufferAttribute(pos, i2);
  n.crossVectors(
    ab.subVectors(b, a),
    ac.subVectors(c, a)
  ).normalize();
  // n.y > 0.35 = upward-facing = dak (rest = wand of vloer)
  (n.y > 0.35 ? roofFaces : wallFaces).push(i0, i1, i2);
}

// Twee groups op de geometrie, met material-indices 0 (muur) en 1 (dak)
geom.clearGroups();
geom.addGroup(0, wallFaces.length, 0);
geom.addGroup(wallFaces.length, roofFaces.length, 1);
node.material = [muurMat, dakMat];

Error handling

  • Roofer crash: per-gebouw fallback naar synthetic. Andere gebouwen onaangetast.
  • Tile niet gevonden in S3 (coverage-gap): synthetic fallback voor dat gebouw.
  • Mesh hoogte < 1m: synthetic fallback (interpretatie: roofer leverde alleen LOD 0 footprint terug).
  • Geen footprint geleverd: fail-fast met error in response.
  • Modal cold start error: front-end polling timeout na 5 min → UI toont "Kon model niet laden".

Bijlage F — Bekende beperkingen voor expert-discussie

Lijstje "lessons learned" en bewust open vragen waar we input op zoeken.

Coverage van DHMV II open data

De S3 bucket bevat niet heel Vlaanderen. Gaten:

  • X = 98.000–129.500 → Gent centrum, Lokeren, Aalst centrum
  • X = 162.000–193.500 → Hoogstraten, Turnhout, Geel, Leuven

Voor adressen in deze zones valt onze pipeline terug op de synthetische geometrie. Vraag aan expert: bestaat er een complete bron (DHMV III? betaald?) die we automatisch kunnen aanspreken?

Classificatie

Alle non-ground returns zitten in klasse 1 ("unclassified"). We hebben dit omzeild met --bld-class 1, maar dat betekent dat ook bomen, antennes en straatmeubilair binnen de footprint als bouwpunten worden geïnterpreteerd. Roofer's interne plane-fitting filtert dit grotendeels, maar perfect is het niet.

Vraag aan expert: is het zinvol om een externe classifier (PDAL? Lidar360? machine learning?) tussen LAZ download en roofer-aanroep te zetten?

DHMV-versie

Huidige bron: DHMV II (2013–2015). DHMV III (2018-2020) of nieuwer bestaat maar niet op deze open S3 bucket. Vraag aan expert: weet u of er een open download is voor DHMV III? Of is het uitsluitend via betaalde toegang van het AGIV?

Context-vrije reconstructie

Roofer reconstrueert per gebouw geïsoleerd. Bij rijwoningen of dichtbebouwde straten kan dit leiden tot kleine inconsistenties bij gedeelde nokken/muren. We sturen momenteel één footprint per call (één Feature in de GeoJSON), niet de hele rij.

Vraag aan expert: is het beter om alle gebouwen op een perceel als één multi-feature GeoJSON aan roofer te geven? Roofer ondersteunt batch-input. Onze keuze voor één gebouw per aanroep was simpliciteit, niet kwaliteit.

Geen vegetation-filter

We doen geen pre-pass om bomen/vegetatie te verwijderen. Voor bouwfootprints die deels onder een boom liggen (vrij vaak in Vlaamse dorpen) krijgt roofer dus deels boom-punten als "dakpunten" mee. Het effect is doorgaans klein maar niet nul.

Geen kwaliteits-feedback aan front-end

Roofer levert rf_rmse_lod22 en rf_pt_density per gebouw, maar wij parsen die niet terug naar de front-end. Bij lage kwaliteit (RMSE > 2m, density < 5/m²) zouden we de gebruiker kunnen waarschuwen of een vrijwaring kunnen tonen.

Synthetic fallback geometrie

Onze fallback maakt enkel schilddak of plat dak. Geen mansarde, geen zadeldak, geen dakkapellen, geen complex L/T-vormig gebouw. Voor 80% van de huizen is dit acceptabel visueel, maar niet representatief. Vraag aan expert: kennen we een lichte geometrische primitive-bibliotheek (e.g. CompenGB, BuildingsGen) die we als upgrade kunnen inzetten voor de fallback?
